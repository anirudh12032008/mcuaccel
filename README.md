# mcuaccel

An int8 CNN accelerator (conv, depthwise conv, fully connected) memory-mapped into a PicoRV32 SoC,
bit-exact with [mcugrad](third_party/mcugrad)'s int8 simulator, plus an mcugrad backend that emits
accelerator command chains and driver C. Research project: the claims were pre-registered before any
datapath RTL existed, and every number below is generated from `results/` by a script. A value shown
as "pending" has no result file yet.

Everything is simulation (Verilator) or synthesis (Yosys + nextpnr, ECP5 LFE5U-85F). No board was used;
FPGA wall-clock and power are open items in [HARDWARE_TODO.md](HARDWARE_TODO.md).

## Architecture

```
  mcugrad int8 graph --> mcuaccel_backend --> model.c + descriptor chains --> riscv gcc --> firmware
                              (pack, split, emit; software fallback for ops the RTL lacks)

     +----------+   corv32 bus   +------------------+   port A    +-------------------------+
     | PicoRV32 |--------------->| soc_interconnect |------------>| soc_ram (true dual port)|
     +----------+                |  RAM | regs | io |             +-----------^-------------+
                                 +---------+--------+                  port B | (private, 32-bit)
                                           | start / desc addr / status       |
                                   +-------v----------------------------------+--------+
                                   | mcuaccel_top (P output channels per tile)         |
                                   | regs -> fetch -> ctrl (descriptor FSM, credits)   |
                                   |   align -> mac_array (4 lanes x P) -> requant     |
                                   |   wbuf / pbuf (weights, per-channel params)       |
                                   |   -> writer (int8 outputs back to RAM)            |
                                   +---------------------------------------------------+
```

CPU and accelerator use different RAM ports, so there is no arbiter. The CPU writes a descriptor
chain address and `START`, the accelerator streams activations one word per cycle, the CPU polls `STATUS`.
Full block diagram and normative timing: [docs/DESIGN.md](docs/DESIGN.md).

## Quickstart

```sh
scripts/bootstrap.sh          # fetches OSS CAD Suite + xPack RISC-V GCC into tools/, creates .venv/
                              # (reuses ../corv32/tools if present)
source scripts/env.sh
git submodule update --init   # third_party/mcugrad
make lint                     # Verilator -Wall + Yosys hierarchy check
make test                     # cocotb + pytest (excludes slow tests; make test-slow runs them)
make sim                      # builds build/sim/Vsoc_top, the whole-SoC Verilator model
make clean-clone-check        # clone to a temp dir, bootstrap, lint + test
```

## Claims and results

Claims C1-C5 and their thresholds are defined in [docs/SPEC.md](docs/SPEC.md) section 6 (C1: speedup >= 10 on
both networks at P=8; C1b: >= 100 on cifar_mobilenet; C2: bit-exactness; C3: <= 6000 LUT4 / 40 MULT18X18D /
12 DP16KD; C4: the pre-registered cycle model predicts within 20% per command and 10% per network; C5:
saturation curve over P). Generated by `experiments/make_readme_tables.py`; do not edit between the markers.

## Reproduce

```sh
source scripts/env.sh
make reproduce                       # everything below, in order; hours
REPRODUCE_QUICK=1 make reproduce     # smoke run: 1 image x 1 run, P=8 only, quick M3, one synth job;
                                     # results/, paper/ and README are restored afterwards
```

`make reproduce` runs: SoC simulator build, `run_baseline.py`, `run_drv_timing.py`, `run_m3.py`,
`run_soc.py` (timing for P in 1,2,4,8,16; profile + C4b at P=8; C2c over 100 images), the synthesis sweep
(`run_syn_sweep.sh`, 52 jobs), `compare_m1.py` when the STAMP logs exist, `make_deviations.py`, `plot_m6.py`, `make_macros.py`, the paper (`tectonic`), then this README's tables and
`FINAL_REPORT.md`. C4a needs `results/m6_stamps_*.json` (`run_soc.py --P <P> --stamps`, run separately) and then `experiments/compare_m1.py`, which writes `results/m6_pred_vs_meas.csv`.

## Repository layout

| path | contents |
|---|---|
| `model/` | M1 architecture exploration and bandwidth model (pre-registered predictions) |
| `rtl/accel/` | accelerator RTL, written from scratch (`mcuaccel_*`) |
| `rtl/soc/` | SoC: RAM, interconnect, CPU adapter, console (`soc_*`) |
| `tb/` | cocotb tests (`unit`, `accel`, `soc`) |
| `sim/` | Verilator C++ harness for full-system runs |
| `backend/` | `mcuaccel_backend`: int8 graph to commands + driver C, software fallback |
| `sw/` | firmware: crt0, linker script, driver, build script |
| `syn/` | Yosys / nextpnr ECP5 flows and extraction |
| `experiments/` | scripts that produce `results/` and the generated tables and macros |
| `results/` | raw CSV/JSON with seed, commit, environment |
| `paper/` | LaTeX (IEEEtran); numbers via generated macros |
| `docs/` | SPEC, DESIGN, DECISIONS, BLOCKERS, ENVIRONMENT, PRIOR_ART |
| `third_party/` | mcugrad (submodule), corv32 (vendored subset), picorv32 (vendored) |
